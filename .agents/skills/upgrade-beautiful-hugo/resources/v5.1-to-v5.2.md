# Upgrade Beautiful Hugo v5.1 to v5.2

v5.2 removes jQuery, moves the theme CSS and JS into `assets/`, fetches self-hosted
vendor files at build time, and uses the Hugo 0.146 template layout. The minimum
Hugo version does not change (0.146.2).

Do the steps in order. Step 1 is required for every site. Steps 2 to 5 apply only
if the check command finds something.

## 0. Baseline

```bash
git status --short          # commit or stash first
hugo --minify               # build v5 once
cp -r public /tmp/before-v5-2 # keep the output to compare later
```

## 1. Point the site at v5.2 (required)

The module path does not change: v5.2 stays `github.com/halogenica/beautifulhugo/v5`.

**Hugo module**

```bash
hugo mod get -u github.com/halogenica/beautifulhugo/v5
hugo mod tidy
```

**Git submodule**

```bash
git -C themes/beautifulhugo fetch --tags
git -C themes/beautifulhugo checkout v5.2.0
git add themes/beautifulhugo
```

**Copy in `themes/`** — replace the directory with the v5.2 source.

## 2. Remove jQuery from custom scripts

The theme no longer loads jQuery. Sites that use `$` or `jQuery` must load it
themselves or use plain DOM APIs.

```bash
grep -rn 'jQuery\|\$(' layouts assets static --include='*.js' --include='*.html'
```

For each hit, either rewrite it with `document.querySelector` and
`addEventListener`, or add a jQuery `<script>` tag to
`layouts/partials/scripts_custom.html` before the code that needs it.

Also delete site copies of `static/js/jquery-*.js`; the theme no longer ships one.

## 3. Fix references to the old asset paths

Theme CSS and JS moved from `static/css/` and `static/js/` to `assets/css/` and
`assets/js/`. The theme now bundles them, minifies them in production builds only,
fingerprints them, and adds an SRI `integrity` attribute.

```bash
grep -rn 'css/main\.css\|css/dark\.css\|js/main\.js\|js/load-photoswipe\.js\|beautifulhugo/static' layouts assets hugo.toml
```

- A `<link>` or `<script>` in `head_custom.html` or `footer_custom.html` that
  points at a theme file under `static/` gets a 404. Delete the tag; the theme
  loads its own bundle.
- Site files, such as `static/css/user.css`, are not affected. Keep them.
- To change a theme stylesheet or script, put a file with the **same path** under
  the site's `assets/` directory, for example `assets/css/main.css`. The site file
  wins. Do not minify it by hand.

## 4. Check the `selfHosted` setting

Applies only to sites with `Params.selfHosted = true`.

v5.2 fetches Bootstrap, KaTeX JS, Highlight.js, PhotoSwipe, and Fuse.js from the
pinned URLs in `data/beautifulhugo/vendor.toml`, checks each file against its SRI
hash, and publishes it under `vendor/`. The vendored copies are gone from the
theme's `static/` directory.

- The first build needs network access. Later builds read Hugo's `getresource`
  cache.
- In CI, cache `HUGO_CACHEDIR` and let the build reach the CDN once.
- To keep the cache forever, add to the **site** configuration (Hugo does not
  merge `[caches]` from a theme):

  ```toml
  [caches.getresource]
    dir = ":cacheDir/:project"
    maxAge = -1
  ```

## 5. Refresh copied theme templates

v5.2 uses `layouts/_partials/`, `layouts/_shortcodes/`, and `layouts/_markup/`, and
renames `single.html` to `page.html`, `terms.html` to `taxonomy.html`, and
`index.json` to `home.json`. **Site overrides in the legacy directories still work,
so no rename is necessary.**

But a partial copied from v5 and edited is now out of date: it misses the new
cached blocks, the deferred asset flags, and the publication and video features.

```bash
ls layouts/partials layouts/shortcodes layouts/_default 2>/dev/null
```

For each file that is a copy of a theme file, diff it against the v5.2 version and
port the local edits:

```bash
diff <(git -C <theme-path> show v5.2.0:layouts/_partials/footer.html) layouts/partials/footer.html
```

Also confirm the author configuration uses the new key; `[author]` at the top level
is an error in v5.2:

```toml
[Params.author]
  name = "..."
```

## 6. Build and compare

```bash
hugo --minify --panicOnWarning
diff -rq /tmp/before-v5-2 public | head -40
```

Expect different file names for the theme CSS and JS (they are fingerprinted) and
a smaller script list (no jQuery). Open a post page and check: dark mode toggle,
the table-of-contents panel, search, image galleries, and math.

## 7. Optional: adopt the new v5.2 features

Hugo does not merge `[markup]` or `[frontmatter]` from a theme, so these go in the
**site** configuration.

- **Math only on pages that need it** — enable the Goldmark passthrough extension:

  ```toml
  [markup.goldmark.extensions.passthrough]
    enable = true
    [markup.goldmark.extensions.passthrough.delimiters]
      block = [['\[', '\]'], ['$$', '$$']]
      inline = [['\(', '\)']]
  ```

- **Math without JavaScript** — `Params.mathRender = "server"` renders KaTeX at
  build time. It needs the passthrough extension and the KaTeX engine.
- **Markdown image attributes** — set
  `[markup.goldmark.parser] wrapStandAloneImageWithinParagraph = false` so
  `{width=300}` reaches the image render hook.
- **Smaller search index** — `Params.searchSections` and
  `Params.searchContentWords`.
- **New options** — `Params.share_img` (default social image),
  `Params.mobileMenuPosition`, `[[Params.author.custom]]` for social icons that the
  built-in registry does not cover.
- **New shortcodes** — `video`, `icon`, and the publication page type.

See `exampleSite/hugo.toml` and the pages under `exampleSite/content/page/` for
complete examples.
